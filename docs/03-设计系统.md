# 03 设计系统

> 状态：v0.3（决策落地）· 2026-11-05  
> 本文定义 token 分层、视觉规范、主题机制与设计协作流程。具体实现见 [02 架构设计](./02-架构设计.md)。

---

## 1. 设计原则

面向企业内部业务系统，优先级与消费级产品不同：信息密度高、任务重复、用户长时间使用、权限与流程复杂。设计系统遵循：

1. **高效优先**：在可读性前提下提高密度；表格、表单、筛选、批量操作是核心场景。
2. **清晰可预期**：状态、层级、反馈明确；相同交互在不同组件中保持一致。
3. **克制**：视觉服务于信息，不用大面积品牌色、重阴影、复杂动效。
4. **可覆盖**：业务方能通过 token / CSS 变量 / `class` 调整，而不是 fork 组件。
5. **包容**：键盘可操作、屏幕阅读器可理解、支持中文 / 英文 / RTL、支持暗色与低动效偏好。

参考对象：

- **API 习惯**：Ant Design（Form.Item、Table.columns、message、ConfigProvider）。
- **Token / BEM 结构**：TDesign。
- **视觉克制与组件边界**：Semi Design。
- 只参考模式，不复制代码与视觉资产；三者均为 MIT，但仍应保持自主实现与品牌差异。

> **没有 Figma / 设计稿源文件。** 视觉与交互以 TDesign / Ant Design / Semi Design 的公开文档与 Demo 为参考，由前端在文档站 TSX Demo / 设计说明中落地，设计与技术负责人评审。参考组件与实现不一致时，以评审结论为准并回写文档。

## 2. Token 体系

### 2.1 三层结构

| 层级 | 作用 | 示例 | 谁使用 |
| --- | --- | --- | --- |
| Primitive | 原始色阶、尺寸、字体 | `--ui-blue-6`、`--ui-space-4` | 构建期 / 主题生成 |
| Semantic | 语义角色 | `--ui-color-primary`、`--ui-color-text-secondary` | 组件 SCSS、业务覆盖 |
| Component | 组件级微调 | `--ui-button-height`、`--ui-table-row-height` | 组件内部、业务微调 |

规则：

- 组件 SCSS **禁止硬编码颜色/尺寸**，只能引用 Semantic 或 Component 变量。
- Primitive 只允许在 token 生成层和极少数布局计算中使用。
- 业务方优先覆盖 Semantic；需要局部微调时覆盖 Component。
- 所有 token 必须有类型、说明、默认值；新增/重命名走设计系统评审。

### 2.2 命名规范

```text
--ui-{category}-{role}-{state?}
```

| 类别 | 示例 |
| --- | --- |
| 颜色 | `--ui-color-primary`、`--ui-color-primary-hover`、`--ui-color-text-secondary` |
| 背景 | `--ui-color-bg-container`、`--ui-color-bg-layout`、`--ui-color-bg-elevated` |
| 边框 | `--ui-color-border`、`--ui-color-border-secondary` |
| 填充 | `--ui-color-fill`、`--ui-color-fill-secondary` |
| 字体 | `--ui-font-family`、`--ui-font-size-md`、`--ui-line-height-md` |
| 间距 | `--ui-space-xs`、`--ui-space-sm`、`--ui-space-md` |
| 圆角 | `--ui-radius-sm`、`--ui-radius-md`、`--ui-radius-lg` |
| 阴影 | `--ui-shadow-sm`、`--ui-shadow-md`、`--ui-shadow-popup` |
| 动效 | `--ui-motion-duration-fast`、`--ui-motion-ease` |
| 层级 | `--ui-z-index-dropdown`、`--ui-z-index-modal` |
| 组件 | `--ui-button-height-md`、`--ui-table-row-height` |

### 2.3 Token 源文件（DTCG 示意）

```json
{
  "color": {
    "blue": {
      "5": { "$type": "color", "$value": "#5a8bff" },
      "6": { "$type": "color", "$value": "#2f6bff" }
    },
    "gray": {
      "1": { "$type": "color", "$value": "#ffffff" },
      "2": { "$type": "color", "$value": "#fafafa" },
      "3": { "$type": "color", "$value": "#f5f5f5" }
    }
  },
  "semantic": {
    "color": {
      "primary": { "$type": "color", "$value": "{color.blue.6}" },
      "primary-hover": { "$type": "color", "$value": "{color.blue.5}" },
      "text-primary": { "$type": "color", "$value": "rgba(0, 0, 0, 0.88)" },
      "bg-container": { "$type": "color", "$value": "{color.gray.1}" }
    }
  }
}
```

构建产物：

```css
:root {
  --ui-blue-6: #2f6bff;
  --ui-color-primary: var(--ui-blue-6);
  --ui-color-primary-hover: var(--ui-blue-5);
  --ui-color-text-primary: rgba(0, 0, 0, 0.88);
  --ui-color-bg-container: #ffffff;
}

[data-ui-theme='dark'] {
  --ui-color-text-primary: rgba(255, 255, 255, 0.85);
  --ui-color-bg-container: #1f1f1f;
  /* ... */
}
```

使用 `outputReferences: true`，让 Semantic 变量引用 Primitive，方便主题切换与调试。

## 3. 色彩

### 3.1 色板

| 语义 | 默认色相 | 用途 |
| --- | --- | --- |
| Primary | Blue | 主操作、选中、链接、聚焦 |
| Neutral | Gray | 文本、背景、边框、禁用 |
| Success | Green | 成功、通过、在线 |
| Warning | Amber | 警告、待处理、风险提示 |
| Danger | Red | 错误、删除、失败、危险操作 |
| Info | Cyan / Blue | 信息提示、进行中 |

> **v0.3 / Q16 已定**：`Button` 的 `color` 默认值为 `primary`（主蓝），不传 `color` 时按上表 Primary 渲染；`neutral` 必须显式传入。与 06 §2.2 / §3 组件模板的 `?? 'primary'` 及 02 §6.1 类型注释一致。视觉克制由 `variant`（默认 `solid`，可退到 `outline` / `text`）与主色按钮出现频次控制，不靠改默认色。

每个色相生成 **10 级色阶**（1 最浅，10 最深），构建期用 `colorjs.io` 在 OKLCH 空间生成，输出 hex 作为稳定运行时值；`color-mix()` 可用于业务侧渐进增强，但不作为 token 的唯一来源。

生成规则：

- 以品牌主色为基准，保持感知亮度均匀；
- 1–3 用于浅背景/边框，4–5 用于 hover/浅色强调，6 为主色，7–8 用于 active/深色，9–10 用于深色文本/暗色背景；
- 构建期校验（**v0.2 修订，按 WCAG 2.1 分档**）：
  - 正文文本对背景 ≥ 4.5:1，大号文本（≥18.66px bold / 24px）≥ 3:1 —— **不达标直接让构建失败**；
  - 仅用于「非必要辅助信息」的 token 单列一档，按 ≥ 3:1 校验并标注用途，**禁止用于正文**；
  - 交互控件的**可识别边界 / 图标 / 焦点指示** ≥ 3:1（WCAG 1.4.11）；纯装饰性分割线与默认边框不参与该判定，但需在 token 说明中标注 `decorative`；真正的控件边界另用 `--ui-color-border-strong`；
  - 禁用态（`text-disabled`）豁免，但不得单独承载信息；
  - 暗色主题单独跑同一套校验。

### 3.2 语义映射（亮色）

| Token | 值（示例） | 用途 |
| --- | --- | --- |
| `--ui-color-primary` | `blue-6` | 主按钮、选中、链接 |
| `--ui-color-primary-hover` | `blue-5` | hover |
| `--ui-color-primary-active` | `blue-7` | active |
| `--ui-color-primary-bg` | `blue-1` | 浅色背景 |
| `--ui-color-primary-border` | `blue-3` | 浅色边框 |
| `--ui-color-text-primary` | `rgba(0,0,0,.88)` | 主文本 |
| `--ui-color-text-secondary` | `rgba(0,0,0,.65)` | 次要文本 |
| `--ui-color-text-tertiary` | `rgba(0,0,0,.55)`（≈4.7:1，v0.2 修正） | 辅助文本；原 `.45` 实测仅 3.35:1，不满足正文 4.5:1 |
| `--ui-color-text-disabled` | `rgba(0,0,0,.25)` | 禁用 |
| `--ui-color-text-inverse` | `#fff` | 深色背景上的文本 |
| `--ui-color-bg-layout` | `#f5f7fa` | 页面背景 |
| `--ui-color-bg-container` | `#fff` | 卡片/表格/表单容器 |
| `--ui-color-bg-elevated` | `#fff` | 弹层 |
| `--ui-color-bg-mask` | `rgba(0,0,0,.45)` | 遮罩 |
| `--ui-color-border` | `#d9d9d9` | 装饰性默认边框（≈1.41:1，标注 `decorative`，不承担控件边界识别） |
| `--ui-color-border-strong` | `#949494`（≈3.06:1） | 输入框 / 按钮等**可识别控件边界**，满足 WCAG 1.4.11 |
| `--ui-color-border-secondary` | `#f0f0f0` | 分割线 |
| `--ui-color-fill` | `#f5f5f5` | 填充/占位 |
| `--ui-color-fill-secondary` | `#fafafa` | 次级填充 |

### 3.3 暗色

暗色单独定义语义值，不做反色：

| Token | 值（示例） |
| --- | --- |
| `--ui-color-text-primary` | `rgba(255,255,255,.85)` |
| `--ui-color-text-secondary` | `rgba(255,255,255,.65)` |
| `--ui-color-text-tertiary` | `rgba(255,255,255,.45)` |
| `--ui-color-bg-layout` | `#0f0f0f` |
| `--ui-color-bg-container` | `#1f1f1f` |
| `--ui-color-bg-elevated` | `#262626` |
| `--ui-color-border` | `#424242`（decorative，≈1.64:1 on #1f1f1f） |
| `--ui-color-border-strong` | `#8a8a8a`（≈4.7:1 on #1f1f1f） |
| `--ui-color-border-secondary` | `#303030` |
| `--ui-color-fill` | `#262626` |

暗色下品牌色需要提高亮度/降低饱和度，构建期单独生成暗色色阶，而不是直接复用亮色 6 级。

### 3.4 状态色使用

- 成功/警告/错误必须同时有**图标或文案**，不能只靠颜色。
- 危险操作（删除、停用）使用 danger；普通取消使用 neutral。
- 链接色与主色一致；已访问链接不做区分（企业系统以操作入口为主）。
- 表格中的状态标签使用浅色背景 + 深色文本，避免大面积高饱和色。

## 4. 字体与排版

### 4.1 字体族

```css
--ui-font-family:
  -apple-system, BlinkMacSystemFont, 'Segoe UI', 'PingFang SC',
  'Hiragino Sans GB', 'Microsoft YaHei', 'Helvetica Neue', Arial, sans-serif;
--ui-font-family-code:
  'SFMono-Regular', Consolas, 'Liberation Mono', Menlo, monospace;
```

- 不引入 Web Font，避免内部网络与 CSP 问题。
- 数字场景（表格、金额、统计）使用 `font-variant-numeric: tabular-nums`。
- 中英文混排使用系统字体栈；行高略高于西文默认。

### 4.2 字号与行高

| Token | 字号 | 行高 | 用途 |
| --- | --- | --- | --- |
| `--ui-font-size-xs` | 12px | 20px | 辅助说明、标签 |
| `--ui-font-size-sm` | 13px | 20px | 紧凑表格、次要信息 |
| `--ui-font-size-md` | 14px | 22px | 正文、表单、按钮 |
| `--ui-font-size-lg` | 16px | 24px | 卡片标题、强调 |
| `--ui-font-size-xl` | 20px | 28px | 页面小标题 |
| `--ui-font-size-2xl` | 24px | 32px | 页面标题 |
| `--ui-font-size-3xl` | 30px | 38px | 大标题 / 空状态 |
| `--ui-font-size-4xl` | 38px | 46px | 结果页数字 |

字重：400（正文）、500（强调/按钮）、600（标题）。不使用 700 以上，避免中文过重。

### 4.3 排版规则

- 正文默认 14px；表格/表单不因密度低于 12px。
- 标题层级最多 3 级；页面标题使用 20/24px，不滥用大字号。
- 段落最大宽度 720px（文档站），业务页面按布局。
- 金额/数量右对齐；文本左对齐；表头与内容对齐方式一致。
- 截断：单行 `text-overflow: ellipsis`；多行使用 `-webkit-line-clamp`（企业浏览器均支持）。

## 5. 间距、尺寸与布局

### 5.1 间距

4px 基准：

| Token | 值 | 用途 |
| --- | --- | --- |
| `--ui-space-0` | 0 | — |
| `--ui-space-1` | 2px | 紧凑内联 |
| `--ui-space-2` | 4px | 图标与文本 |
| `--ui-space-3` | 6px | 小间距 |
| `--ui-space-4` | 8px | 控件内边距 |
| `--ui-space-5` | 12px | 表单项内 |
| `--ui-space-6` | 16px | 卡片内边距、栅格 gutter |
| `--ui-space-7` | 20px | 区块间距 |
| `--ui-space-8` | 24px | 卡片 padding、页面区块 |
| `--ui-space-9` | 32px | 大区块 |
| `--ui-space-10` | 40px | 页面级 |
| `--ui-space-11` | 48px | 页面级 |
| `--ui-space-12` | 64px | 空状态 / 结果页 |

语义别名（括号为 **px 值**，不是 `--ui-space-N` 的编号，v0.2 明确）：`--ui-space-xs` = `--ui-space-2`(4px)、`sm` = `--ui-space-4`(8px)、`md` = `--ui-space-5`(12px)、`lg` = `--ui-space-6`(16px)、`xl` = `--ui-space-8`(24px)、`2xl` = `--ui-space-9`(32px)。

标称「4px 基准」，`--ui-space-1`(2px) 与 `--ui-space-3`(6px) 是允许的半步例外，仅用于图标与文本微调；组件内边距优先用 4 的倍数。

### 5.2 控件高度

| Size | 高度 | 字号 | 典型场景 |
| --- | --- | --- | --- |
| `small` | 24px | 12px | 表格内编辑、紧凑工具栏 |
| `medium` | 32px | 14px | 默认表单、按钮 |
| `large` | 40px | 16px | 登录页、强调操作 |

### 5.3 圆角与边框

| Token | 值 | 用途 |
| --- | --- | --- |
| `--ui-radius-sm` | 4px | 标签、输入框内元素 |
| `--ui-radius-md` | 6px | 按钮、输入框、卡片 |
| `--ui-radius-lg` | 8px | 弹层、抽屉 |
| `--ui-radius-full` | 999px | 头像、圆形按钮 |

边框默认 1px；分割线使用 `--ui-color-border-secondary`；不使用粗边框强调，改用背景/字重。

### 5.4 阴影

| Token | 值 | 用途 |
| --- | --- | --- |
| `--ui-shadow-sm` | `0 1px 2px rgba(0,0,0,.05)` | 卡片 hover |
| `--ui-shadow-md` | `0 4px 12px rgba(0,0,0,.08)` | 下拉、Popover |
| `--ui-shadow-lg` | `0 8px 24px rgba(0,0,0,.12)` | Modal、Drawer |
| `--ui-shadow-focus` | `0 0 0 2px var(--ui-color-primary-bg)` | 聚焦环 |

暗色下阴影加深透明度，避免“发灰”。

### 5.5 栅格与断点

- 24 栅格，`gutter` 默认 16px。
- 断点：`xs < 576`、`sm ≥ 576`、`md ≥ 768`、`lg ≥ 992`、`xl ≥ 1200`、`xxl ≥ 1600`。
- 页面布局：Header 56/64px；Sider 200/240px，可折叠 64px；Content padding 16/24px。
- 表格/表单在 `md` 以下改为纵向布局；**桌面优先**（v0.2 与 07 §3.2 对齐）：平板（≥768px）要求可用，375px 只做「不溢出、不截断关键信息」冒烟，**不做移动端组件适配、不出移动端视觉基线**。

## 6. 动效

| Token | 值 | 用途 |
| --- | --- | --- |
| `--ui-motion-duration-fast` | 100ms | hover、颜色变化 |
| `--ui-motion-duration-base` | 150ms | 展开、淡入 |
| `--ui-motion-duration-slow` | 200ms | Modal / Drawer |
| `--ui-motion-ease` | `cubic-bezier(0.2, 0, 0, 1)` | 默认 |
| `--ui-motion-ease-out` | `cubic-bezier(0.16, 1, 0.3, 1)` | 进入 |

原则：

- 动效用于表达状态变化，不用于装饰。
- 表格排序、筛选、分页不做大幅动画。
- `prefers-reduced-motion: reduce` 时全部降为 0ms，仅保留必要的透明度变化。
- 不使用 JS 动画库；CSS transition / animation 足够。

## 7. 层级（z-index）

| Token | 值 | 用途 |
| --- | --- | --- |
| `--ui-z-index-base` | 0 | 普通内容 |
| `--ui-z-index-sticky` | 100 | 吸顶表头 / Affix |
| `--ui-z-index-dropdown` | 1000 | Dropdown / Select |
| `--ui-z-index-popover` | 1100 | Popover / Tooltip |
| `--ui-z-index-mask` | 1200 | Modal / Drawer 遮罩 |
| `--ui-z-index-modal` | 1210 | Modal |
| `--ui-z-index-drawer` | 1220 | Drawer |
| `--ui-z-index-message` | 1300 | Message |
| `--ui-z-index-notification` | 1310 | Notification |

- `ConfigProvider` 提供 `zIndexBase`（v0.2 机制补充）：组件层不写死数值，统一用 `calc(var(--ui-z-index-base) + <offset>)`；`zIndexBase` 由 ConfigProvider 在挂载时写入作用域元素的 CSS 变量（受 CSP `style-src` 约束，见 01 §6）。严格 CSP 下退化为 `:root` 默认常量。
- 同一层级内后打开的元素在上；不依赖 DOM 顺序的偶然性。

## 8. 密度（Density）

企业系统需要“默认”和“紧凑”两档；通过 `data-ui-density` 切换，不改变控件 `size` 语义。

| 维度 | 默认 | 紧凑 |
| --- | --- | --- |
| 表格行高 | 44px | 36px |
| 表格单元格 padding | 12px 16px | 8px 12px |
| Form.Item 垂直间距 | 24px | 16px |
| Card padding | 24px | 16px |
| Menu item 高度 | 40px | 32px |
| Descriptions item padding | 12px 16px | 8px 12px |
| 页面区块间距 | 24px | 16px |

- 紧凑模式不缩小字号到 12px 以下；表格内可用 `size="small"` 控件。
- 密度是全局偏好，也可局部通过 `ConfigProvider` 或 `data-ui-density` 覆盖。
- 业务方可在用户设置中持久化密度。

## 9. 品牌与多主题

### 9.1 主题维度

```text
品牌（brand-a / brand-b / default）
  × 明暗（light / dark）
  × 密度（default / compact）
  × 方向（ltr / rtl）
```

### 9.2 品牌定制方式

**v1 推荐：构建期主题包**

- `packages/tokens/themes/brand-a.json` 覆盖 Semantic token（主色、圆角、字体等）。
- 构建输出 `theme-brand-a.css`，业务方**先引入默认 `tokens.css`、再引入品牌 CSS**（两者选择器特异性相同，靠顺序决定），然后在根节点设置 `data-ui-brand="brand-a"`；文档与脚手架模板必须固定这个顺序。
- 优点：无运行时色彩计算、体积可控、SSR 无闪烁、可做对比度校验。
- 品牌数量建议 ≤ 5；每个品牌生成亮/暗两套。

**Phase 2：运行时主色**

- `ConfigProvider theme={{ colorPrimary: '#...' }}` 生成 10 级色阶并写入 CSS 变量。
- 需要一个小型 OKLCH → sRGB 生成器（约 2–3 KB），并处理暗色映射。
- 不作为 v1 阻塞项；若业务确实需要用户自定义主题，再实现。

### 9.3 主题切换

```tsx
<ConfigProvider theme="dark" density="compact" locale={zhCN}>
  <App />
</ConfigProvider>
```

- 默认写到 `document.documentElement`；`themeTarget="local"` 时写到包裹元素。
- 切换时只改 `data-*` 与 CSS 变量，不重新渲染组件树。
- SSR 首屏由应用在 HTML 上预设主题，避免闪烁；`theme="system"` 在客户端解析。

---

## 10. 图标

- 默认 16px；导航/工具栏 20px；空状态/结果页 48–64px。
- 线性图标，`stroke-width: 1.75`，`currentColor`，圆角端点。
- 图标与文本间距 4–6px；仅图标按钮必须有 `aria-label`。
- 业务图标与 UI 图标分开：`@ui-design/icons` 只放通用图标；业务图标由业务包维护，避免污染。
- 图标命名使用语义名（`search`、`settings`、`user`），不使用形状名（`magnifier`）。
- 按组件导入（`import { Search } from '@ui-design/icons'`），不使用字符串 `name` 动态查找，避免打包全量图标。
- 需要 RTL 镜像的图标（箭头、返回、缩进）标记 `data-flip`。

---

## 11. 无障碍设计约束

- 正文对比度 ≥ 4.5:1；大文本 ≥ 3:1；控件边界/图标 ≥ 3:1。
- 焦点态必须可见：2px 主色 ring + 2px offset；不允许 `outline: none` 无替代。
- 状态不能只靠颜色：成功/警告/错误配图标或文本。
- 点击目标最小 24×24px；表格行内操作可用 24px 图标按钮，但需足够间距。
- 动效遵循 `prefers-reduced-motion`。
- 表单：label 必须关联；必填有视觉与语义标记；错误信息通过 `aria-live` 播报。
- 表格：表头 `scope` / `aria-sort`；行选择有可读标签；空状态有说明。
- 日期：键盘可完成全部选择；月份切换有 live region 提示。
- 暗色/高对比模式下重新校验对比度。

```text

        ▼

        │

        │
        ▼

        │
        ├─ dist/css/tokens.css
        ├─ dist/ts/tokens.ts
        └─ dist/json/tokens.json
        │
        ▼
组件 SCSS 使用 Semantic / Component 变量
        │
        ▼

```

约定：

- 设计规范以文档站 TSX Demo / 设计说明为准，不依赖 Figma；token 名称必须落到文档与代码，不直接标注 hex（品牌色除外）。
- 新增 token 需要：用途、亮/暗值、对比度、是否组件级；由前端提案，设计/技术负责人评审。
- 组件视觉走查以文档站 Demo 为准；与 TDesign/AntD/Semi 参考不一致时，记录差异与理由并回写文档。
- 每季度做一次 token 清理：合并重复、废弃无引用项、检查命名一致性。
