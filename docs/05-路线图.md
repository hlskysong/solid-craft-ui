## 2. 阶段计划

### Phase 0：决策与 Spike（第 1–2 周）

**目标**：把高风险技术点验证掉，避免进入实现后返工。

| 任务 | 产出 | 验收 |
| --- | --- | --- |
| 确认剩余待定项 | 决策记录 | 团队、registry / CI 平台（含 TS 7 平台包镜像）、正式品牌名；包名暂用 `ui-design`、许可证 MIT 已定 |
| 仓库脚手架 | pnpm workspace + Turborepo + Changesets + lint/test/build | `pnpm build` / `pnpm test` / `pnpm lint` 可跑 |
| TS 7 工具链 | `tsc` 声明产出 + `oxlint --type-aware` + Biome solid + `oxc-parser` API 表 | 四者跑通；`baseUrl` 迁移完成 |
| 包构建 Spike | Vite / Webpack 5 / Rspack 三端消费；SolidStart `"solid"` 条件 + SSR 渲染冒烟 | import、类型、CSS、tree-shaking 正常；SSR 无 `Client-only API` |
| Kobalte 封装 Spike | Select + Dialog | 样式覆盖、键盘、焦点、SSR 正常 |
| Token / 主题 Spike | 亮/暗/密度/品牌切换 | 无闪烁、变量可覆盖 |
| Table Spike | 1 万行可行性 + 固定列方案 | 方案可行；**60fps 性能验收移到 Phase 5**，MVP 不交付虚拟滚动 |
| DatePicker Spike | 基础 + 键盘 + 范围可行性预研 | 中文 locale；含 hydration 冒烟（MVP 验 SSR） |
| Form Spike | Input + Select + 校验 | 错误滚动、字段级更新 |
| 文档 Spike | Demo + 源码 + API 表 + 截图 | 文档站可构建、MVP 基线（light/ltr/default）可跑 |
| TS 7 平台包 | 私有 registry 镜像 20 个平台二进制包 | CI 各架构 `tsc --version` + 声明产出可运行 |
| SSR 双构建 | `"solid"` 条件 + JSX 源码产物可行性 | 消费方可解析、可 SSR 渲染 / hydrate；**MVP 必备产物**，Phase 1 落地 |
| API 草案 | Form / Table / Select / DatePicker | 评审通过（含响应式契约与 `data-*` 口径） |

**Exit**：Spike 结果写入决策记录；未通过项有替代方案；脚手架可支撑纵向切片。**Phase 0 只验可行性，不验收 v1.0 才交付的性能与完整视觉矩阵**（v0.2 修订）。

### Phase 1：基础设施与纵向切片（第 3–5 周）

**目标**：建立可复制的组件开发流水线。

| 工作 | 内容 |
| --- | --- |
| Token 管线 | DTCG → CSS 变量 / TS；亮色 + 暗色骨架；对比度校验 |
| 样式基础 | reset（可选）、base、mixins、BEM 约定、PostCSS |
| ConfigProvider | locale / theme / density / direction / zIndex / portal 骨架 |
| 基础组件 | Button、Icon、Typography、Space、Divider、Layout、Grid |
| 测试设施 | Vitest + Testing Library + jsdom；Playwright + axe + 截图 |
| 文档设施 | 路由、Demo 渲染、源码高亮、API 生成、搜索 |
| CI/CD | lint / typecheck / test / build / size / publint / attw |
| 发布预演 | Changeset + canary 发布到私有 registry |
| 双构建（v0.3 由骨架升为正式产物） | `dist/source/*.jsx` 覆盖每个组件子路径 + `"solid"` 条件导出 + 构建脚本一一对应校验（M4 验收，避免 Phase 6 改 `exports` 结构） |
| 纵向切片 | Button 全流程走通，形成组件模板 |

**Exit**：新组件可以按模板在 1–3 天内完成（简单组件）；CI 全绿；文档站可访问。

> **人力归属（v0.2 补充）**：Token 管线、ConfigProvider、文档站设施、CI/CD 由 **工程师 C + 技术负责人** 共同负责（见 §4），不再出现「基础设施无人认领」。

### Phase 2：表单闭环（第 6–9 周）

**目标**：试点应用能开发完整表单页。

| 周 | 工作 |
| --- | --- |
| 6 | Input、InputNumber、Checkbox、Radio、Switch；FieldContext 协议 |
| 7 | Select（单选/多选/搜索/键盘/弹层）；Form 基础（校验、布局、错误滚动） |
| 8 | DatePicker 基础（单选、locale、键盘；范围仅 Phase 0 可行性预研，不进 MVP）；Upload 基础（customRequest、进度） |

**风险**：Form / Select / DatePicker 三个 L/XL 组件并行，需技术负责人重点 review。

### Phase 7：业务组件与生态（第 29 周起）

- ProTable / ProForm / SearchForm / PageContainer。
- 打印、导出、权限包裹、主题编辑器。
- 图表 / 富文本 / PDF 集成示例。
- 组件请求评审、季度路线图。

### 关键路径与缓冲（v0.2 去编号）

**关键路径**：`Form` → `Table` → `DatePicker` → 试点接入。

- `Form` 是 MVP 的最长路径；若 Phase 0 Spike 后评估超过 4 周，MVP 顺延到第 16–17 周，优先保证质量。
- `Table` 基础可在 Phase 2 末期（第 9 周）由第二名工程师并行启动，不必等表单完全结束。
- `DatePicker` 基础与 `Upload` 基础可并行；范围/时间/时区放 v1.0。
- 组件 spec / 交互说明由前端在文档站 Demo 中提前 1 周给出，设计与负责人评审；否则组件开发会空转。
- 每个 Phase 预留 **10–15% 缓冲**；上述周数是工程净时间，不含审批、假期、试点排期。

> 如果实际进度落后，优先砍 `Tabs`、`Descriptions`、`Upload` 高级、`DatePicker` 范围，而不是降低 A11y / 测试 / 文档标准。

## 7. 试点与推广

### 7.1 试点选择

优先选择：

- 中等复杂度、3 个月内可上线的新页面/新系统。
- 团队愿意反馈、能接受早期 API 调整。
- 有真实表单 + 表格 + 弹窗 + 权限场景。
- 不与关键发布窗口冲突。

避免：

- 核心交易系统的大改版（风险高）。
- 只做静态展示、不需要复杂组件的项目。
- 团队没有前端人力配合的项目。

### 7.2 接入策略

- **增量替换**：新页面先用组件库；老页面不强制重写。
- **不搞大爆炸迁移**：避免一次性替换 AntD / TDesign。
- 提供迁移对照表（Button / Form / Table / Modal 等常用组件）。
- 提供接入检查清单：CSS 引入、ConfigProvider、主题、locale、构建配置。
- 试点期每周一次同步，收集 API 痛点。

### 7.3 推广

- 内部文档站 + 搜索 + 示例。
- 1 小时入门培训 + 组件专题（Form / Table / DatePicker）。
- Office Hours：每周固定 1 小时。
- 组件需求模板：场景、频率、现有替代方案、参考组件 / 设计说明。
- 版本发布说明 + 迁移指南。
- 度量：接入应用数、页面覆盖率、组件使用频次、问题 SLA。

## 9. 主要风险与缓解

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 范围蔓延（想对齐 AntD 全量） | 延期、质量下降 | 严格 P0/P1/P2；业务组件后置；需求评审 |
| Table / DatePicker / Form 复杂度超预期 | MVP 延期 | Phase 0 Spike；分阶段交付；必要时缩减高级能力 |
| Kobalte 0.x 变更或停维护 | 底层返工 | adapter 隔离；锁版本；保留 fork 选项 |
| 设计资源有限 / 视觉方向不统一 | 组件返工、视觉不一致 | 以 TDesign/AntD/Semi 为参考；前端主导 TSX spec；负责人评审；先用 token 默认值 |
| 试点团队不配合 | 需求失真、推广失败 | 选择意愿强的团队；技术负责人驻场；每周同步 |
| 浏览器 / 微前端兼容问题 | 线上故障 | Chrome 最近 30 版基线；真实 Chrome/Edge 测试；Firefox/Safari best effort；qiankun/wujie 示例 |
| SSR / hydration 问题（MVP 起） | 首屏异常 / hydration 误匹配 | Phase 0 验双构建可行性；Phase 1 落地全量子路径；Phase 4 SolidStart 冒烟 + CI 门禁；确定性 ID；Portal 处理 |
| 团队人力不足 | 延期 | 缩减范围；优先 P0；业务组件延后 |
| TS 7 工具链 / Solid 2.0 生态变化 | 升级成本 | 锁版本；oxlint/tsgolint + Biome 适配层；季度评估 |
| CSS 冲突 / 宿主样式污染 | 视觉异常 | 前缀、低特异性、无全局 reset、隔离示例 |

| 许可证 / 合规 | 法务风险 | 已定 MIT（v0.3 / ADR-020）；自研实现；参考不复制；依赖许可证审查 |

| 视觉回归矩阵过大拖垮 MVP（v0.2 新增） | `0.1.0` 无法发布 | 分档：MVP light/ltr/default，v1.0 补齐四套 |
