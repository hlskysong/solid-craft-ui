# 06 工程规范

> 状态：v0.3（决策落地）· 2026-11-05  
> 本文是组件实现、测试、评审、发布的统一标准。与 [04 组件范围 §8 Definition of Done](./04-组件范围.md#8-definition-of-done组件完成标准) 配套使用。

---

## 1. 仓库与协作

### 1.1 分支策略

- 主干开发：`main` 始终保持可构建、可发布 canary。
- 功能分支：`feat/button`、`fix/select-clear`、`docs/table-api`，短生命周期（≤ 3 天为宜）。
- 发布：`main` 合并后自动 canary；打 tag 发布 stable。
- 长期维护：从 tag 拉 `release/1.x`，只接受修复。

### 1.2 Commit 规范

Conventional Commits：

```text
feat(button): support icon position
fix(select): keep focus after clear
docs(form): add async validation example
test(table): cover row selection
chore(deps): bump kobalte to 0.13.14
```

- `type`：feat / fix / docs / test / refactor / perf / build / ci / chore / revert。
- `scope`：组件名或包名，小写。
- 破坏性变更：`feat(select)!: ...` + Changeset major。
- 一个 PR 尽量只做一件事；组件 + 文档 + 测试可以在同一 PR。

### 1.3 PR 要求

- 标题符合 Conventional Commits。
- 描述包含：改了什么、为什么、截图/录屏（视觉变更）、测试方式、风险。
- 用户可见变更必须包含 Changeset。
- CI 全绿：lint、typecheck、unit、build、size、publint、attw、必要时的 Playwright。
- 至少 1 名组件 owner review；涉及 API / 视觉 / A11y 的变更需对应负责人 review。
- 不提交 `console.log`、调试代码、临时文件。

## 2. 代码规范

### 2.1 TypeScript 7

- 固定 `typescript@7.0.2`，使用原生 `tsc` 做类型检查与声明产出；不降级 6.x。
- `strict: true`、`noUncheckedIndexedAccess: true`；不使用 `any`（确需时 `unknown` + 守卫，并注释）。
- 不使用 `baseUrl`（TS 7 / tsgolint 不支持）；路径别名用 `paths` + `moduleResolution: bundler`。
- 不使用依赖 TS 旧 compiler API 的项目工具；API 表生成用 `oxc-parser`。`attw` 自带解析器，只分析声明产物，不绑定项目 TS 版本。
- 类型检查：`tsc --noEmit`；类型感知 lint：`oxlint --type-aware`。
- **tsconfig 约束（v0.2 实测）**：`baseUrl` 已移除（TS5102）；`rootDir` 必须显式（TS5011）；`include: ["src/**/*"]` + `skipLibCheck: true` 必填，否则误扫 `node_modules` 内 `.d.ts`。`declaration` / `emitDeclarationOnly` / `declarationMap` / `jsx: preserve + jsxImportSource` 均已实测可用。
- **平台二进制包**：TS 7 的 `tsc` 依赖 20 个 `@typescript/typescript-<platform>` 包；私有 registry 必须镜像，CI 各架构验证 `tsc --version`。
- 公共 API 必须有显式类型；内部函数可推断。
- Props 用 `interface`；联合类型用 `type`；不使用 `enum`（用 `as const` 联合）。
- 公共类型加 JSDoc，至少包含说明与 `@default`。
- 不导出内部类型（Kobalte、TanStack、内部 context）。
- 泛型组件保持简单；不要为了“完全类型安全”引入难以理解的类型体操。
- 使用 `satisfies` 校验常量对象，而不是宽泛断言。

### 2.2 Solid 专项规则

Solid 专项规则由 Biome `solid` domain 承担（`noSolidDestructuredProps`、`useSolidForComponent`）；oxlint 不负责 Solid 语义判断。未被自动规则覆盖的约定（如 `createMemo` 替代 `createEffect`）靠 review checklist 约束。

| 规则 | 说明 |
| --- | --- |
| **不解构 props** | `const { value } = props` 会丢失响应性；用 `props.value` 或 `splitProps`。由 Biome `solid` domain 的 `noSolidDestructuredProps` 检查 |
| **派生用 `createMemo`** | 不要用 `createEffect` 同步派生状态 |
| **复杂状态用 `createStore`** | Form / Table / Tree；简单状态用 `createSignal` |
| **`batch` 多字段更新** | 避免中间态渲染 |
| **`onCleanup` 释放资源** | 事件监听、Observer、定时器、请求 |
| **`createUniqueId`** | 生成 a11y ID；禁止随机数作为 SSR 初始 ID |
| **`isServer` 守卫** | 模块顶层不访问 `window` / `document` |
| **`Show` / `For` / `Index`** | 条件与列表渲染；稳定 key 用 `For` |
| **`Dynamic`** | 多态 `as` 场景，谨慎使用 |
| **`children` helper** | 需要多次读取 children 时使用，避免重复创建 |
| **`untrack`** | 明确不需要追踪时使用，并注释原因 |
| **`classList`** | 条件类名优先 `classList`；复杂合并用 `classNames` 工具 |

示例：

```tsx
// ✅ 正确：状态一律 data-*，不生成 modifier class
export function Button(props: ButtonProps) {
  const [local, rest] = splitProps(props, ['variant', 'color', 'size', 'class', 'children']);
  const classes = createMemo(() => classNames('ui-button', local.class));

  return (
    <button
      class={classes()}
      data-variant={local.variant ?? 'solid'}
      data-color={local.color ?? 'primary'}
      data-size={local.size ?? 'medium'}
      {...rest}
    >
      {local.children}
    </button>
  );
}

// ❌ 错误：解构 props，丢失响应性
export function Button({ variant, size, children }: ButtonProps) {
  return <button class={`ui-button--${variant}`}>{children}</button>;
}
```

### 2.3 文件与命名

| 类型 | 规范 | 示例 |
| --- | --- | --- |
| 组件文件 | PascalCase | `Button.tsx`、`DatePicker.tsx` |
| 目录 | kebab-case | `components/date-picker/` |
| 样式 | kebab-case | `date-picker.scss` |
| 类型 | `types.ts` | `components/table/types.ts` |
| 测试 | `*.test.tsx` | `Button.test.tsx` |
| Demo | kebab-case | `demos/basic.tsx`、`demos/with-icon.tsx` |
| Hook | `use-*.ts` | `use-controllable.ts` |
| 工具 | kebab-case | `class-names.ts` |

- 组件使用**命名导出**；Demo 文件可用 default export。
- `index.ts` 只做公共导出，不放实现。
- 避免 `index.ts`  barrel 造成循环依赖；组件内部按文件直接 import。

### 2.4 导入顺序

```ts
// 1. 外部依赖
import { createMemo, splitProps } from 'solid-js';

// 2. 内部跨包
import { Icon } from '@ui-design/icons';

// 3. 同包上层
import { useLocale } from '../../locale';

// 4. 同级
import { classNames } from './utils';
// 注意：组件库源码不 import SCSS，样式由独立构建产出（见 §4）
```

> 组件库源码不运行时 import SCSS；样式由独立构建产出。若使用 CSS Modules，需单独评审。

## 3. 组件实现模板

```tsx
// components/button/types.ts
import type { JSX } from 'solid-js';

export interface ButtonProps
  extends Omit<JSX.ButtonHTMLAttributes<HTMLButtonElement>, 'type'> {
  /** 视觉变体，默认 solid */
  variant?: 'solid' | 'outline' | 'dashed' | 'text' | 'link';
  /** 语义色，默认 primary（v0.3 / Q16 已定）；视觉克制由 variant 与出现频次控制，不靠改默认色 */
  color?: 'primary' | 'neutral' | 'success' | 'warning' | 'danger';
  /** 尺寸，默认 medium */
  size?: 'small' | 'medium' | 'large';
  /** 是否占满父容器宽度 */
  block?: boolean;
  /** 加载态；加载时禁用点击 */
  loading?: boolean;
  /** 图标 */
  icon?: JSX.Element;
  /** 图标位置，默认 start */
  iconPosition?: 'start' | 'end';
  /** 形状，默认 default */
  shape?: 'default' | 'round' | 'circle';
  /** 原生 button type，默认 button */
  htmlType?: 'button' | 'submit' | 'reset';
}
```

```tsx
// components/button/Button.tsx
import { splitProps, Show } from 'solid-js';
import { classNames } from '../../utils/class-names';
import type { ButtonProps } from './types';

export function Button(props: ButtonProps) {
  const [local, rest] = splitProps(props, [
    'variant',
    'color',
    'size',
    'block',
    'loading',
    'icon',
    'iconPosition',
    'shape',
    'htmlType',
    'class',
    'children',
    'disabled',
    'onClick',
  ]);

  const variant = () => local.variant ?? 'solid';
  const color = () => local.color ?? 'primary';
  const size = () => local.size ?? 'medium';
  const shape = () => local.shape ?? 'default';
  const disabled = () => local.disabled || local.loading;

  return (
    <button
      {...rest}
      type={local.htmlType ?? 'button'}
      class={classNames('ui-button', local.class)}
      data-size={size()}
      data-variant={variant()}
      data-color={color()}
      data-shape={shape()}
      data-block={local.block ? 'true' : undefined}
      data-loading={local.loading ? 'true' : undefined}
      disabled={disabled()}
      aria-busy={local.loading ? 'true' : undefined}
      onClick={(event) => {
        if (disabled()) return;
        local.onClick?.(event);
      }}
    >
      <Show when={local.icon && local.iconPosition !== 'end'}>{local.icon}</Show>
      <span class="ui-button__content">{local.children}</span>
      <Show when={local.icon && local.iconPosition === 'end'}>{local.icon}</Show>
    </button>
  );
}
```

```ts
// components/button/index.ts
export { Button } from './Button';
export type { ButtonProps } from './types';
```

要点：

- `type` 默认 `button`，避免在 Form 中误触发表单提交。
- `loading` 时 `disabled` + `aria-busy`。
- `data-*` 便于样式与测试；**变体 / 尺寸 / 状态不生成 modifier class**（v0.2 统一，见 §4 的 SCSS），避免模板产出死代码。
- 事件透传但可拦截；不覆盖用户的 `onClick` 语义。
- `class` / `style` 合并。

## 4. 样式规范

- 只使用 token 变量；禁止硬编码颜色、间距、圆角、阴影、z-index。
- BEM 命名只用于静态结构；**变体 / 尺寸 / 状态一律用 `data-*` 属性选择器**（v0.2 定稿，与 §3 模板一致）；根节点尽量 `:where(.ui-xxx)` 降低特异性。
- 状态用 `data-*`，不用大量状态类。
- 不写全局选择器（`body`、`html`、`*`）；reset 单独入口。
- 不使用 `!important`。
- 不依赖 DOM 层级选择器。
- 动画只使用 `transform` / `opacity`；避免布局抖动。
- 焦点态用 `outline: 2px solid var(--ui-color-primary); outline-offset: 2px;`；**禁止无替代的 `outline: none`**，`--ui-shadow-focus` 是浅色值，单独使用不可见（v0.2 修正）。
- 暗色 / 紧凑 / RTL 通过变量与逻辑属性实现，不写三套重复样式。
- 每个组件 SCSS 文件只负责自己的类名；共享 mixin 放 `styles/mixins.scss`。
- 组件样式必须能被业务方用普通类名覆盖；必要时提供 CSS 变量。

示例：

```scss
@use '../../styles/mixins' as *;

:where(.ui-button) {
  display: inline-flex;
  align-items: center;
  justify-content: center;
  gap: var(--ui-space-2);
  height: var(--ui-button-height-md);
  padding-inline: var(--ui-button-padding-x-md);
  border: 1px solid transparent;
  border-radius: var(--ui-radius-md);
  font-size: var(--ui-font-size-md);
  line-height: var(--ui-line-height-md);
  cursor: pointer;
  transition:
    background-color var(--ui-motion-duration-fast) var(--ui-motion-ease),
    border-color var(--ui-motion-duration-fast) var(--ui-motion-ease),
    color var(--ui-motion-duration-fast) var(--ui-motion-ease);

  &:focus-visible {
    outline: 2px solid var(--ui-color-primary);
    outline-offset: 2px;
  }

  &[data-size='small'] {
    height: var(--ui-button-height-sm);
    padding-inline: var(--ui-button-padding-x-sm);
    font-size: var(--ui-font-size-xs);
  }

  &[data-variant='solid'][data-color='primary'] {
    background: var(--ui-color-primary);
    color: var(--ui-color-text-inverse);

    &:hover:not(:disabled) {
      background: var(--ui-color-primary-hover);
    }
  }

  &:disabled {
    cursor: not-allowed;
    opacity: 0.5;
  }
}
```

## 5. 测试规范

### 5.1 单元 / 行为测试

- 使用 Vitest + `@solidjs/testing-library` + `@testing-library/user-event` + **`@testing-library/jest-dom`**（`toBeDisabled()` 等匹配器来源，v0.2 补入依赖表；vite-plugin-solid 会自动检测并注入 setupFiles）。
- 查询优先 `getByRole` / `getByLabelText` / `getByText`，避免 `container.querySelector`。
- 覆盖：
  - 默认渲染与变体；
  - 受控 / 非受控；
  - 事件与回调参数；
  - `ref`；
  - `class` / `style` 合并；
  - 禁用 / 加载 / 错误；
  - 键盘交互；
  - 边界（空数据、长文本、非法输入）。
- 不测试实现细节（内部 signal、私有 class）。
- 不使用大段 snapshot；SSR 可用 snapshot。
- 异步用 `await screen.findBy...` / `waitFor`；谨慎使用 fake timers。

示例：

```tsx
import { render, screen } from '@solidjs/testing-library';
import userEvent from '@testing-library/user-event';
import { Button } from '../Button';

it('does not fire onClick when loading', async () => {
  const onClick = vi.fn();
  render(() => (
    <Button loading onClick={onClick}>
      保存
    </Button>
  ));

  const button = screen.getByRole('button', { name: '保存' });
  expect(button).toBeDisabled();
  await userEvent.click(button);
  expect(onClick).not.toHaveBeenCalled();
});
```

### 5.2 浏览器 / A11y 测试

- Playwright 针对文档站 Demo 页面运行。
- 每个 P0 组件至少一个键盘路径测试：
  - Tab 进入 / 离开；
  - Enter / Space 触发；
  - Esc 关闭弹层；
  - 方向键在 Select / Menu / Tabs / DatePicker 中工作。
- axe 扫描：`@axe-core/playwright`，禁止 serious / critical。
- 焦点断言：打开 Modal 后焦点在弹层内；关闭后归还触发元素。
- 定位断言：Select / Tooltip 不被视口裁剪；滚动容器内定位正确。

### 5.3 视觉回归

- 每个组件 Demo 截图；**按版本分档（v0.2）**：
  - **MVP 必过**：light / ltr / default，viewport 1280 + 768；
  - **v1.0 补齐**：dark、compact、rtl（布局敏感组件）、四套矩阵；
  - 375px 仅做「不溢出、不截断关键信息」冒烟，**不作为移动端适配验收**（与 03 §5.5、07 §3.2 对齐）。
- 固定：字体、时区、locale、动画关闭、随机数据。
- 浏览器：Chrome / Edge 为基线；Firefox / Safari best effort，只做关键 Demo 冒烟。
- 基线随 PR 审核；不允许无说明的大面积 diff。
- CI 使用固定 Playwright Docker 镜像，避免渲染差异。

### 5.4 SSR / 消费方（按版本分档）

- **MVP**：`examples/solid-start` 构建 + `renderToString` 快照 + hydration 冒烟（light / ltr / default 单档），无 `console` hydration warning；组件模块顶层无 `window` 访问；`"solid"` 条件导出在每个组件子路径均可解析。
- **v1.0**：暗色 / 紧凑 / RTL 全矩阵 SSR 回归、流式渲染、Portal 细则与已知限制清单。
- `examples/vite` / `examples/webpack` / `examples/rspack` 构建；检查 CSS、类型、tree-shaking。
- 发布前用 `pnpm pack` 产物做一次真实安装测试。

### 5.5 覆盖率

- 初始目标：行覆盖 70%，P0 组件关键路径 100%。
- 不以覆盖率作为唯一指标；bug 回归测试优先。
- 覆盖率报告在 CI 中展示，不阻塞（除非明显下降）。

## 6. 无障碍检查清单

每个组件 PR 必查：

- [ ] 语义元素正确（button / input / table / dialog / list）。
- [ ] 键盘可完成核心操作；焦点顺序合理。
- [ ] 焦点态可见（2px 主色 outline + 2px offset）；不使用无替代的 `outline: none`。
- [ ] 图标按钮有 `aria-label`；装饰图标 `aria-hidden="true"`。
- [ ] 表单 label 关联；必填有语义；错误 `aria-invalid` + `aria-describedby`。
- [ ] 弹层焦点陷阱、Esc 关闭、关闭后焦点归还。
- [ ] 动态内容（Message / Notification / 表单错误）有 `aria-live`。
- [ ] 颜色对比度达标（文本 4.5:1、大文本 / 可识别控件边界 3:1；装饰性边框标注 `decorative`）；状态不只靠颜色。
- [ ] 触摸目标 ≥ 24×24px。
- [ ] `prefers-reduced-motion` 降级。
- [ ] RTL 下布局与图标方向正确。
- [ ] axe 无 serious / critical。

## 7. API 评审清单

新增/修改公共 API 时评审：

- [ ] 命名符合约定（size / variant / color / status / onChange）。
- [ ] 受控 / 非受控行为完整。
- [ ] `ref`、`class`、`style` 可用。
- [ ] 事件参数有意义；不泄漏内部对象。
- [ ] 泛型必要且可推导；无 `any`。
- [ ] 默认值合理；文档标注。
- [ ] 与现有组件一致（如 `open` vs `visible`，统一用 `open`）。
- [ ] 不暴露底层库类型。
- [ ] 兼容 SSR / 微前端。
- [ ] 有 A11y 方案。
- [ ] 有 i18n 文案方案。
- [ ] 有迁移/弃用方案（若破坏性）。
- [ ] 包体积影响可接受。

## 8. 文档要求

每个组件页面必须包含：

1. **何时使用**：适用/不适用场景。
2. **基础 Demo**：最小可用示例。
3. **变体 / 尺寸 / 状态**：视觉与交互差异。
4. **受控用法**：`value` / `onChange`。
5. **表单集成**：与 `Form.Item` 的用法。
6. **边界**：空数据、长文本、禁用、错误、加载。
7. **API 表**：自动生成 + 手工说明。
8. **设计指南**：间距、颜色、图标、文案。
9. **无障碍**：键盘、ARIA、屏幕阅读器注意事项。
10. **FAQ / 已知问题**。

Demo 规范：

- 每个 Demo 独立文件，默认导出组件，附带 `demo` 元数据。
- 不依赖外部网络；数据本地 mock。
- 不包含 `console.log`。
- 代码可直接复制运行。
- 复杂 Demo 提供“为什么这样写”的说明。

## 9. 发布流程

### 9.1 Changeset

- 每个用户可见变更添加 Changeset：
  - `patch`：bug 修复、样式微调、文档。
  - `minor`：新组件、新 prop、非破坏性增强。
  - `major`：破坏性 API / 行为变更（1.0 后）。
- Changeset 描述面向使用者，写“发生了什么、如何迁移”。

### 9.2 发布步骤

```bash
pnpm install --frozen-lockfile
tsc --version      # 确认平台二进制包已安装（私有 registry 需镜像 20 个 @typescript/typescript-* 包）
pnpm lint          # oxlint --type-aware + biome lint + stylelint
pnpm typecheck     # tsc --noEmit
pnpm test
pnpm build
pnpm size
pnpm publint
pnpm attw
# 校验各包 LICENSE 存在且 package.json 声明 "license": "MIT"
# CI 通过后
pnpm changeset version
pnpm build
pnpm changeset publish
```

- `main` 合并后自动发布 canary：`0.x.y-canary.YYYYMMDD`。
- stable 通过 tag 触发；发布前跑 `examples/*` 冒烟。
- 发布后：
  - 在 `examples/vite` / `examples/webpack` / `examples/rspack` / `examples/solid-start` 安装新版本验证（后者含 SSR 渲染 + hydration）；
  - 检查 registry 上的 `dist/esm`、`dist/source`、`exports` 的 `solid` 条件、CSS 与 `LICENSE`；
  - 更新文档站版本；
  - 发布内部公告。

### 9.3 回滚

- 不删除已发布版本；使用 `npm deprecate` 标记问题版本。
- 发布 patch 修复；必要时回退文档站版本。
- 严重问题在内部公告中说明影响范围与临时规避方案。

## 10. 弃用策略

- 先标记：JSDoc `@deprecated` + 开发环境 `console.warn`（只警告一次）。
- 文档标注替代方案与迁移示例。
- 至少保留 2 个 minor 版本；major 移除。
- 移除前在 CHANGELOG 中列清单。
- 不静默改变行为；行为变更视为破坏性。

---

## 11. 安全规范

- 默认按文本渲染；禁止在组件内部使用 `innerHTML`。
- 需要渲染 HTML 的组件（如 `Typography`）必须显式开启，并在文档中要求调用方 sanitize。
- 链接：校验 `href`，阻止 `javascript:`；`target="_blank"` 自动加 `rel="noopener noreferrer"`。
- 上传：前端校验类型/大小只是体验，文档强调服务端必须再次校验。
- 不记录敏感信息到 console / 错误上报。
- 依赖：锁定版本、定期 audit、审查新依赖的许可证与维护状态。
- CSP：不注入 `<style>`；运行时 CSS 变量需在文档说明 `style-src` 要求。
- SSR：默认转义；不拼接未转义的 HTML 字符串。

---

## 12. 性能规范

- 遵守 [02 架构 §4.6 体积预算](./02-架构设计.md#46-产物体积预算)。
- 新增依赖前评估：体积、tree-shaking、维护状态、许可证。
- 不在组件渲染路径创建大对象 / 大数组；用 `createMemo` 缓存。
- 列表使用稳定 key；虚拟化场景避免全量渲染。
- 事件监听使用 passive（滚动/触摸）并清理。
- 避免布局抖动：动画只改 `transform` / `opacity`。
- 大表格 / 大表单用 Playwright + Performance API 做基准；回归超过 20% 需说明。
- CI 运行 `size-limit`；超标阻塞合并（除非有批准）。

## 14. 常见反模式

| 反模式 | 后果 | 正确做法 |
| --- | --- | --- |
| 解构 props | 丢失响应性 | `splitProps` / `props.x` |
| 用 effect 同步派生状态 | 额外渲染、循环 | `createMemo` |
| 在组件内硬编码颜色 | 主题失效 | 使用 token |
| 用 DOM 查询改样式 | 脆弱、SSR 问题 | 状态驱动 + `data-*` |
| 暴露 Kobalte 类型 | 升级破坏 | 内部 adapter + 自有类型 |
| 每个组件一个全局 store | 状态耦合 | Context + 局部状态 |
| 用 `any` 绕过泛型 | 类型失效 | 泛型约束 / `unknown` |
| props 里传 signal 函数却不归一（v0.2 新增） | 字段值不更新 / 类型错乱 | 按响应式契约用 `resolveValue()`；Context 注入 getter |
| 同时生成 modifier class 和 `data-*`（v0.2 新增） | 两套机制并存，CSS 匹配不上、出现死代码 | 状态统一 `data-*` |
| 只为 Demo 写样式 | 生产不可用 | Demo 与生产同源 |
| 先做视觉后做 A11y | 返工 | A11y 与 API 同步设计 |
| 一次 PR 改多个组件 | 难评审、难回滚 | 小 PR，按组件拆分 |
