# 02 架构设计

> 状态：v0.3（决策落地）· 2026-11-05  
> 本文定义仓库结构、包边界、构建产物、样式/主题、公共 API、测试与文档架构。具体版本依据见 [01 技术选型](./01-技术选型.md)。

---

## 1. 总体架构

```text
┌──────────────────────────────────────────────────────────────┐
│                        消费方应用                              │
│  Vite / Webpack 5 / Rspack / SolidStart / 微前端容器                    │
│  import { Button } from '@ui-design/core'                     │
│  import '@ui-design/core/styles.css'                          │
└───────────────▲──────────────────────────────▲───────────────┘
                │                              │
┌───────────────┴──────────────┐  ┌────────────┴───────────────┐
│      @ui-design/core         │  │      @ui-design/icons       │
│  components / styles / locale│  │  curated icons / svg       │
│  hooks / utils / primitives  │  │                            │
└───────────────▲──────────────┘  └────────────▲───────────────┘
                │                              │
┌───────────────┴──────────────────────────────┴───────────────┐
│                     @ui-design/tokens                        │
│   DTCG JSON → CSS variables / TS / JSON                      │
└──────────────────────────────────────────────────────────────┘

开发与质量设施：
apps/docs（文档站） · apps/playground（调试） · examples/*（消费方冒烟）
Vitest · Playwright · axe · size-limit · publint · attw · oxlint · Biome · Stylelint · Changesets
```

设计原则：

1. **依赖单向**：`tokens` 不依赖任何包；`icons` 只依赖 `solid-js`；`core` 依赖 `tokens` / `icons`；应用层依赖三者。
2. **公共 API 不泄漏底层库类型**：Kobalte / TanStack 的类型不直接出现在 `@ui-design/core` 的导出中，避免升级时破坏使用者。
3. **样式与 JS 解耦**：JS 不隐式 import CSS；消费者显式引入全局或按组件 CSS，构建行为可预测。
4. **单版本、少包**：内部使用优先降低版本错配，所有包 fixed versioning。

### 2.1 为什么是三个包，而不是一个或十个

- **`tokens` 独立**：设计 token 的变更频率、评审流程与组件不同；可从 TDesign / AntD / Semi 参考中提炼，供主题工具、其他端复用。
- **`icons` 独立**：图标体积大、按需引入要求高；独立包可避免每次改图标都发 core。
- **`core` 聚合**：组件、样式、locale、hooks 放在一个包，减少内部版本错配；通过 subpath exports 实现按组件引入。
- 不再拆 `utils` / `locale` / `styles` 独立包：内部使用没有必要，反而增加版本与构建复杂度。

所有包使用 **fixed versioning**：`@ui-design/core@1.2.0` 对应 `icons@1.2.0`、`tokens@1.2.0`。

## 3. 包导出与消费方式

### 3.1 `@ui-design/core` 的 `package.json`（示意）

```json
{
  "name": "@ui-design/core",
  "version": "0.1.0",
  "type": "module",
  "license": "MIT",
  "sideEffects": ["**/*.css"],
  "files": ["dist", "README.md", "LICENSE"],
  "exports": {
    ".": {
      "types": "./dist/types/index.d.ts",
      "solid": "./dist/source/index.jsx",
      "import": "./dist/esm/index.js",
      "default": "./dist/esm/index.js"
    },
    "./button": {
      "types": "./dist/types/components/button/index.d.ts",
      "solid": "./dist/source/components/button/index.jsx",
      "import": "./dist/esm/components/button/index.js"
    },
    "./styles.css": "./dist/styles/index.css",
    "./styles/*": "./dist/styles/*",
    "./locale/*": {
      "types": "./dist/types/locale/*.d.ts",
      "import": "./dist/esm/locale/*.js"
    },
    "./package.json": "./package.json"
  },
  "peerDependencies": {
    "solid-js": "^1.9.0"
  },
  "dependencies": {
    "@ui-design/icons": "workspace:^",
    "@kobalte/core": "^0.13.14",
    "@tanstack/solid-table": "^9.3.1",
    "@internationalized/date": "^3.12.4",
    "@floating-ui/dom": "^1.8.0"
  },
  "publishConfig": {
    "registry": "https://your-private-registry/",
    "access": "restricted"
  }
}
```

要点：

- **`solid-js` 是 peerDependency**，绝不打包进库；微前端 / Module Federation 下必须单例。
- **运行时依赖作为 dependencies**：Kobalte / TanStack / date / floating-ui 由包管理器安装，不内联进产物，避免重复与版本锁死。
- **MVP 依赖最小化（v0.2）**：`@tanstack/solid-virtual`（虚拟滚动）与 `@atlaskit/pragmatic-drag-and-drop`（行拖拽 / 排序）在 v1.0 对应功能落地时再加入，避免 MVP 背负未使用依赖的体积与审计面。
- **`sideEffects` 只保留 CSS**：JS 必须可 tree-shake。
- **根导出 + 子路径导出**：根导出方便；子路径导出用于严格 tree-shaking 和老构建工具。
- **`"solid"` 条件是 MVP 必备（v0.3 / ADR-018）**：每个含组件的导出都必须同时给出 `solid`（保留 JSX 的 `dist/source/*.jsx`）与 `import`（编译后 `dist/esm/*.js`）两条；由构建脚本做一一对应校验，并由 `publint` / `attw` / `examples/solid-start` 三重门禁验证，缺失即发布阻塞。CSS 与 `./package.json` 路径不需要 `solid` 条目。
- **包 scope 暂用 `ui-design`（v0.3 / ADR-020）**：`@ui-design/*` 与 CSS 前缀 `ui-` 集中在单一常量与构建脚本中定义，正式品牌名确定后只改配置，不动组件 API。
- **类型路径与 JS 路径一一对应**，由 `publint` / `attw` 校验。

### 3.2 消费方式

```tsx
// 推荐：按组件引入（tree-shaking 最稳）
import { Button } from '@ui-design/core/button';
import '@ui-design/core/styles.css';

// 或：根导出
import { Button, Input, Form } from '@ui-design/core';
```

CSS 采用**显式引入**，原因：

- 避免 JS 隐式副作用，SSR / Webpack / Rspack / 微前端行为可预测。
- 允许两种粒度：
  - 全量：`import '@ui-design/core/styles.css'`（tokens + base + 所有组件）
  - 按需：`import '@ui-design/core/styles/base.css'` + `import '@ui-design/core/styles/components/button.css'`
- 后续可提供 `unplugin-ui-design` 自动按需引入 CSS，但不作为 v1 前置条件。

> 注意：CSS 显式引入意味着业务方必须记得加。文档、脚手架模板、lint 提示中都要强调；`examples/*` 作为正确用法基准。

### 3.3 `solid` 条件导出

Kobalte 的做法是同时提供编译后 JS 与保留 JSX 的 `.jsx`，通过 `"solid"` condition 让消费方编译器选择。**v0.2 确认这不是可选优化，而是 SSR 的必要条件；v0.3 依据 Q17 决策把它提前到 MVP。**

vite-plugin-solid 官方说明：Solid 的 JSX 在构建期按目标编译（客户端 DOM / 服务端 SSR / 可 hydrate），**只发布编译后 JS 等于锁死目标**，产物是 client-only DOM，服务端渲染会抛 `Client-only API called on the server side`，且无法 hydrate。官方建议发布 `{ "solid": "./dist/source/*.jsx", "import": "./dist/*.js" }` 双入口，由消费方按目标重新编译；每个子路径导出都要有对应的 `solid` 条目。

| 阶段 | 产物 | SSR 能力 |
| --- | --- | --- |
| **MVP（v0.1，v0.3 修订）** | `dist/esm` 编译产物 + `dist/source/*.jsx` 源码产物；全量 `"solid"` 条件导出 | **可用**：`renderToString` + hydration 冒烟（light / ltr / default 单档）为 M4 验收项 |
| **Phase 1（v0.3 调整）** | 双构建从「骨架」升级为正式构建：源码产物覆盖每个组件子路径 + CI 一一对应校验 | 具备并冻结 `exports` 结构 |
| **v1.0 / Phase 6** | 暗色 / 紧凑 / RTL 全矩阵 SSR 回归、流式渲染、Portal 细则、已知限制清单 | 完整支持 |

v0.2 把双构建提前到 Phase 1 建骨架，v0.3 再提前为 MVP 必备产物：既避免到 Phase 6 才改 `exports` 结构与所有子路径导出造成破坏性变更，也满足「试点主力 SPA / MPA、但 SSR 使用正常」的业务要求（ADR-018）。

## 4. 构建管线

### 4.1 任务顺序

```text
tokens:build  →  icons:build  →  core:build  →  docs:build
                                      │
                                      ├─ ESM (Vite, preserveModules) → dist/esm
                                      ├─ SOURCE (保留 JSX) → dist/source  ← "solid" 条件
                                      ├─ DTS (tsc --emitDeclarationOnly)
                                      └─ CSS (Sass + PostCSS)
```

Turborepo 配置示意：

```json
{
  "$schema": "https://turbo.build/schema.json",
  "tasks": {
    "build": {
      "dependsOn": ["^build"],
      "outputs": ["dist/**"]
    },
    "typecheck": { "dependsOn": ["^build"] },
    "test": { "dependsOn": ["build"], "outputs": ["coverage/**"] },
    "lint": {},
    "dev": { "cache": false, "persistent": true },
    "docs:build": { "dependsOn": ["build"], "outputs": ["dist/**"] }
  }
}
```

### 4.2 Core JS 构建

- Vite library mode，入口 `src/index.ts`。
- `rollupOptions.output.preserveModules: true`，保留目录结构，确保子路径导入与 tree-shaking。
- `external`：用函数匹配 `solid-js` 及其所有子路径（`solid-js/web`、`solid-js/store` 等）以及所有 dependencies，避免遗漏子路径导入。
- `build.minify: false`：库产物不压缩，交给消费方；保留 sourcemap。
- `vite-plugin-solid`：`dist/esm` 按客户端 DOM 目标构建；`dist/source` **保留 JSX 不做 Solid 编译**（仅转 TS → JSX），由消费方按 SSR / CSR 目标自行编译。`hydratable` 是编译期选项，只作用于库自身产物，不能替代 `"solid"` 条件导出。
- 输出：`dist/esm/**/*.js` + `dist/source/**/*.jsx` + 对应 sourcemap；两条链都保留 `preserveModules` 目录结构，子路径必须一一对应，由构建脚本校验（v0.3 / ADR-018）。
- 不产出 CJS：内部应用均使用现代构建工具；若确有 Webpack 4 需求，再单独评估，不默认支持。
- **TS 7 平台包（v0.2 实测）**：`tsc` 依赖 20 个 `@typescript/typescript-<platform>` 原生二进制包；私有 registry 需镜像，CI 各架构需验证 `tsc --version` 可用，否则 `--frozen-lockfile` 安装成功但构建失败。
- **Phase 0 验证**：Vite 8 若默认使用 Rolldown，需确认 `preserveModules`、CSS 抽取、sourcemap 行为；不满足则 JS 改用 Rollup 单独构建，Vite 只负责文档站与测试。

消费方示例与库源码解耦：`examples/vite`、`examples/webpack`、`examples/rspack`、`examples/solid-start` 都安装 `pnpm pack` 后的 tarball，而不是通过 workspace 直接引用源码，确保验证的是真实发布产物。Rspack 2.x 使用 `babel-loader` + `babel-preset-solid` 处理 Solid 1.9 的 TSX；`@rspack/core` 内置 SWC 暂不提供 Solid JSX transform。

### 4.3 声明文件

- `tsconfig.build.json`（v0.2 按 TS 7.0.2 实测补齐）：
  - `declaration: true`、`emitDeclarationOnly: true`、`declarationMap: true`
  - `outDir: dist/types`、`rootDir: src`（**必须显式**，否则 TS5011）
  - `include: ["src/**/*"]`、`skipLibCheck: true`（否则误扫 `node_modules` 内 `.d.ts` 报错）
  - `jsx: preserve`、`jsxImportSource: solid-js`（实测该组合在 TS 7 下可用，也是官方库模板写法）
  - `moduleResolution: bundler`、`strict: true`、`noUncheckedIndexedAccess: true`
  - 不使用 `baseUrl`（TS 7 已移除，TS5102）；路径别名用 `paths`，相对 tsconfig 解析。
- 使用 TS 7 原生 `tsc` 而非 `vite-plugin-dts`：声明按源文件输出，路径稳定；Phase 0 验证 `declarationMap`、`stripInternal`、`paths` 与 `tsc` / `tsgolint` 的兼容性。
- `ts-morph` 依赖 TS 旧 compiler API，TS 7 下不可用；API 表生成改用 `oxc-parser`（见 §12.3）。
- 公共类型只从 `components/*/index.ts` 导出；内部类型（Kobalte、TanStack）不进入公共 API。

### 4.4 CSS 构建

- 作者态：SCSS。
- 构建：
  1. `sass` 编译 `src/styles/base.scss` → `dist/styles/base.css`。
  2. 拼接 `tokens.css` + `base.css` → `dist/styles/base.css`（顺序：tokens 在前）。
  3. 逐组件编译 `src/components/*/*.scss` → `dist/styles/components/*.css`。
  4. 拼接 `base.css` + 所有组件 CSS → `dist/styles/index.css`。
  5. PostCSS（`autoprefixer` + `postcss-preset-env`）按 browserslist 处理 best-effort 浏览器；不对 Chrome 128+ 做语法降级。
  6. 产出 sourcemap。
- 全局样式入口：
  - `styles.css`：tokens + base + 所有组件样式（不含 reset）。
  - `styles/base.css`：tokens + base（按需引入时的公共前置）。
  - `reset.css`：可选 reset。
  - `styles/components/*.css`：按组件。
- 不把 CSS 打进 JS；不生成 CSS-in-JS。

### 4.5 图标构建

- 从 `lucide-solid` 精选需要的图标，生成 `packages/icons/src/generated/*.tsx`。
- 自有业务图标放 `packages/icons/src/custom/*.svg`，经 SVGO 优化后生成 Solid 组件。
- 每个图标独立模块，`currentColor`、`size="1em"`、`stroke-width` 可覆盖。
- 不导出全量图标；`@ui-design/icons` 根导出只包含精选集，避免误引入全量。

### 4.6 产物体积预算

| 产物 | 预算（gzip） | 说明 |
| --- | --- | --- |
| Button（JS + CSS） | ≤ 6 KB | 基础组件基线 |
| Form + Input + Select | ≤ 25 KB | 不含 DatePicker / Upload |
| Table + Virtual | ≤ 35 KB | 基础表格 + 虚拟滚动 |
| DatePicker | ≤ 30 KB | 含 Calendar / Range |
| Core 全量（不含图标） | ≤ 180 KB | 所有 v1 组件 |
| 单个图标 | ≤ 1 KB | 按需引入 |

预算在 Phase 0 用真实构建校准；超标必须说明原因或拆分。

## 5. 样式架构

### 5.1 Token 分层

```text
Primitive（原始值）
  --ui-blue-1 … --ui-blue-10
  --ui-gray-1 … --ui-gray-10
  --ui-space-1 … --ui-space-12
  --ui-radius-sm / md / lg
        │
        ▼
Semantic（语义）
  --ui-color-primary
  --ui-color-primary-hover
  --ui-color-text-primary
  --ui-color-text-secondary
  --ui-color-bg-container
  --ui-color-border
  --ui-control-height-md
        │
        ▼
Component（组件）
  --ui-button-height
  --ui-button-padding-x
  --ui-table-row-height
```

规则：

- 组件 SCSS **只使用 Semantic / Component 变量**，不直接引用 Primitive（除极少数布局）。
- 业务方覆盖优先改 Semantic 变量；组件级微调改 Component 变量。
- 暗色 / 密度 / 品牌只切换 Semantic / Component 层，Primitive 不动。
- 变量命名：`--ui-{category}-{role}-{state?}`；状态用 `hover` / `active` / `disabled` / `selected`。

### 5.2 类名与选择器

- BEM 只用于**静态结构**：`.ui-button`（块）、`.ui-button__icon`（元素）；静态装饰变体可用 `.ui-button--block`。
- `ui-` / `--ui-` 只是占位前缀；首版发布前必须随品牌确定（如 `acme-` / `--acme-`），发布后更改视为破坏性变更。
- **状态与可枚举变体统一用 `data-*`（v0.2 定稿）**，不再生成 `.ui-button--primary` / `.ui-button--sm` 这类 modifier class，避免 BEM 与 data-* 两套机制并存导致 CSS 匹配不上：
  ```html
  <button class="ui-button" data-variant="solid" data-color="primary" data-size="medium" data-loading="true" disabled>
  ```
- 尺寸取值统一 `small | medium | large`；禁止 `sm` / `md` 简写（v0.1 曾出现三套取值，会导致 `[data-size='small']` 失效）。
- 低特异性：根节点用 `:where(.ui-button)`，内部元素用正常类名。
- 禁止 `!important`；禁止全局 `body` / `html` / `*` 样式（reset 除外，且 opt-in）。
- 不依赖 DOM 结构选择器（如 `.ui-form > div > input`），避免业务包裹层破坏样式。

### 5.3 Reset 与 Base

- `reset.css` 可选：只做最小归一化（box-sizing、margin、font inherit、button 样式重置），不覆盖业务全局排版。
- `base.css`（包含在 `styles.css` 中）：字体、颜色、focus ring、滚动条、禁用态、动画降级。
- 不自动注入 reset；业务方可以继续使用自己的 reset / Tailwind preflight。文档提供冲突排查指南。

### 5.4 暗色 / 密度 / RTL / 品牌

| 维度 | 机制 | 示例 |
| --- | --- | --- |
| 暗色 | `data-ui-theme="dark"` + Semantic 变量覆盖 | `<html data-ui-theme="dark">` |
| 系统主题 | JS 解析 `prefers-color-scheme` 后写 `data-ui-theme` | `ConfigProvider theme="system"` |
| 密度 | `data-ui-density="compact"` + Component 变量覆盖 | 表格行高 44 → 36，Form 间距缩小 |
| RTL | `dir="rtl"` + CSS 逻辑属性 | `margin-inline-start`、`inset-inline-end` |
| 品牌 | `data-ui-brand="brand-a"` 或运行时 CSS 变量覆盖 | 多子公司主题 |
| 字号 | `data-ui-size`? 不单独做；用 `size` prop | 组件级 |

暗色不是简单反色：背景、边框、文本、填充、阴影分别定义；构建期做对比度校验。

### 5.5 主题作用域与 Portal

- 默认主题写在 `document.documentElement`，Portal 到 body 的弹层也能继承。
- `ConfigProvider` 支持 `themeTarget`：
  - `"root"`（默认）：写到 `html`，适合单应用。
  - `"local"`：写到 Provider 包裹元素，适合微前端 / 局部主题。
  - `HTMLElement`：写到指定容器。
- `portalContainer` / `getPopupContainer`：弹层渲染到微前端容器内，避免被宿主样式影响。
- 若主题作用域是 local，弹层必须渲染到同一作用域内，否则变量丢失；文档明确此约束。

### 5.6 微前端 CSS 隔离

- 固定前缀 `ui-`；不使用随机哈希类名。
- 无全局副作用；reset 可选。
- `:where` 降低特异性；业务方普通类名即可覆盖。
- 可使用 `@layer ui.components` 作为增强（Chrome 128+ 已支持）；仍保留固定前缀与低特异性，避免宿主层叠顺序不可控。
- 提供 qiankun / wujie 示例：`ConfigProvider` + `portalContainer` + 单例 `solid-js`。
- 若宿主使用 Tailwind preflight，重点检查 `button`、`input`、`table`、`ul/ol` 的归一化冲突。

## 6. 公共 API 约定

**响应式契约（v0.2 新增，全库强制）**：Solid 不做组件重渲染，props 是 getter。为避免"传值还是传 accessor"在各组件间不一致，统一约定：

| 场景 | 约定 |
| --- | --- |
| 组件 props | 值类 prop 接受 `T`；需要响应式的 prop 同时接受 `Accessor<T>`。组件内部一律用 `resolveValue(v)` 归一（`typeof v === 'function' ? v() : v`），并在 getter 中读取以保留追踪 |
| 受控判定 | 以 `props.value !== undefined` 判定受控，不做真值判断；`defaultValue` 只作为非受控初值 |
| Context 注入 | `FormFieldContext` / `TableContext` 等注入的 `value` / `status` / `disabled` **一律是 getter**（`() => T`），控件通过 `props` 或 `resolveValue` 读取；禁止注入快照值 |
| 示例写法 | JSX 中 `value={userId()}` 与 `rowSelection={{ selectedRowKeys: selectedRowKeys() }}` 保持一致；不出现「同一示例里有的调用 accessor、有的直接传函数」 |
| 派生状态 | 用 `createMemo` 包 `resolveValue(...)`；禁止 `createEffect` 同步到第二份 signal |

> 这条契约是 Form / Table / Select / DatePicker 能否正确联动的前提；API 评审清单（[06 §7](./06-工程规范.md#7-api-评审清单)）必须检查。

### 6.1 命名与 Props

```tsx
export interface ButtonProps
  extends Omit<JSX.ButtonHTMLAttributes<HTMLButtonElement>, 'type'> {
  variant?: 'solid' | 'outline' | 'dashed' | 'text' | 'link';
  /** 语义色，默认 primary（v0.3 / Q16 已定） */
  color?: 'primary' | 'neutral' | 'success' | 'warning' | 'danger';
  size?: 'small' | 'medium' | 'large';
  block?: boolean;
  loading?: boolean;
  icon?: JSX.Element;
  iconPosition?: 'start' | 'end';
  shape?: 'default' | 'round' | 'circle';
  htmlType?: 'button' | 'submit' | 'reset';
}
```

约定：

- 尺寸统一 `small | medium | large`（24 / 32 / 40 px），与 TDesign/AntD 习惯一致。
- 变体统一 `variant` + `color`；表单状态统一 `status: 'error' | 'warning' | 'success'`。
- 继承原生属性；`class` / `style` 合并而不是覆盖。
- `ref` 支持 `HTMLElement` 或回调；不额外发明 `forwardRef`。
- 布尔 prop 用肯定语义：`disabled`、`loading`、`block`、`clearable`、`searchable`。
- 不使用 `isXxx` 前缀；不使用 `onXxxChange` 之外的自定义事件名。

### 6.2 受控 / 非受控

统一模式：

```tsx
interface ControlProps<T> {
  value?: T;
  defaultValue?: T;
  onChange?: (value: T, meta?: ChangeMeta) => void;
}
```

- 有 `value`（`!== undefined`）即受控；无 `value` 用 `defaultValue` 内部状态。
- 受控时内部仍可保留**临时编辑态**（如组合输入、DatePicker 输入串），但必须明确 `editing` 状态机；`Form.Item` 场景下 Form 是唯一数据源，控件不再保留与 `value` 重复的状态（与 [04 §5.2](./04-组件范围.md#52-form) 一致）。
- `value` / `defaultValue` 均按上面的响应式契约支持 `Accessor<T>`。
- `open` / `defaultOpen` / `onOpenChange`；`checked` / `defaultChecked` / `onCheckedChange`。
- 不提供 `onInput` 作为业务语义；原生输入事件按需透传。

### 6.3 组合方式

- **高层扁平 API**：`Select options={...}`、`Table columns={...}`、`Menu items={...}`，符合 AntD 使用习惯。
- **复杂结构暴露子组件**：`Form.Item`、`Form.List`、`DatePicker.RangePicker`、`Table` 的 `columns` 配置。
- **不强制 compound components**：Kobalte 的 `Select.Trigger` / `Select.Content` 留在内部 adapter，业务方使用扁平 API。
- 高级用户可通过 `components` / `renderXxx` 扩展，而不是暴露底层 primitives。

### 6.4 事件与异步

- 事件同步触发；异步逻辑用显式 prop（`beforeUpload`、`validator`、`request`）。
- 事件回调返回 `void`；需要阻止默认行为时提供 `preventDefault` 语义的返回值（如 `beforeUpload` 返回 `false` / `Promise`）。
- 错误通过 `status` / `help` / `onError` 表达；不抛异常到全局。

### 6.5 状态属性与测试钩子

- 根节点输出 `data-*`：`data-size`、`data-variant`、`data-disabled`、`data-loading`、`data-state`、`data-status`。
- 便于 CSS、测试、视觉回归和业务侧定制；不承诺这些属性是公共 API（文档标注为“稳定但非语义 API”）。
- 关键交互元素保留原生语义：`button`、`input`、`table`、`dialog` 等。

### 6.6 泛型

- `Select<T>`、`Table<T>`、`Form<Model>`、`Tree<T>` 支持泛型。
- 公共类型避免 `any`；必要时用 `unknown` + 类型守卫。
- 复杂泛型推导（如 `columns` 的 `dataIndex`）在 v1 保持简单：`dataIndex?: keyof T | string`，不追求完全类型安全的路径推导。

## 7. 状态与响应式约定

- **不解构 props**：`props.value` / `splitProps` / `mergeProps`；Biome `solid` domain 的 `noSolidDestructuredProps` 规则禁止 `const { value } = props`。
- **派生用 `createMemo`**，不用 `createEffect` 同步状态。
- **复杂状态用 `createStore`**（Form、Table、Tree），简单状态用 `createSignal`。
- **受控逻辑抽成 `createControllableSignal`**，避免每个组件重复。
- **Context**：`ConfigProviderContext`、`LocaleContext`、`FormContext`、`FormItemContext`、`TableContext`；Context 缺失时给出明确错误。
- **不引入全局 store**（Redux / Zustand）；组件库不拥有应用状态。
- **清理**：`onCleanup` 移除监听、Observer、定时器；SSR 下不注册浏览器 API。
- **批量更新**：多字段同步更新用 `batch`，避免中间态渲染。

## 8. SSR 与 Hydration

> **v0.3 边界**（ADR-018）：试点主力 SPA / MPA，不强依赖 SolidStart；但**组件库必须 SSR 可用**。下列 SSR-safe 约束在 MVP 即为验收项；`renderToString` + hydration 冒烟（light / ltr / default 单档）在 M4 验收。暗色 / 紧凑 / RTL 全矩阵 SSR 回归、流式渲染与 Portal 细则仍属 v1.0 目标态。原因见 [§3.3](#33-solid-条件导出) 与 [01 §6](./01-技术选型.md#6-ssr--微前端--安全约束)。

- 模块顶层禁止 `window` / `document` / `navigator` / `matchMedia`。
- 使用 `isServer` 分支；只在 `onMount` 注册浏览器 API。
- ID 使用 `createUniqueId`，并加组件前缀；禁止 `Math.random()` 作为初始 ID。
- Portal / 弹层：
  - 默认客户端渲染；SSR 输出占位或空。
  - `ConfigProvider` 的 `portalContainer` 在客户端解析。
- 主题：
  - SSR 由应用在 `<html>` 上预设 `data-ui-theme`，避免首屏闪烁。
  - `ConfigProvider` 的 `theme="system"` 在客户端挂载后解析；服务端默认 `light`。
- 日期 / 相对时间：
  - 服务端与客户端时区可能不同；需要确定性的场景显式传 `timeZone`，或客户端渲染。
- CSS：
  - 消费方负责引入 `styles.css`；SSR 框架需把 CSS 注入 HTML。
  - 文档提供 SolidStart / Vite SSR 示例。
- 验证（**MVP / M4**，Phase 4 执行）：
  - `renderToString` 快照（P0 组件）；
  - `examples/solid-start` 构建 + SSR 渲染 + hydration 冒烟（light / ltr / default 单档）；
  - CI 检查 console hydration warning；`"solid"` 条件在 Vite / Webpack 5 / Rspack / SolidStart 均可解析。
- 验证（**v1.0**，Phase 6 执行）：暗色 / 紧凑 / RTL 全矩阵 SSR 回归、流式渲染、Portal 细则与已知限制清单。

## 10. 无障碍（A11y）

- 目标：WCAG 2.1 AA；关键组件通过 axe + 手工键盘测试。
- Kobalte 负责 Dialog / Select / Menu / Tabs / Tooltip 等原语的焦点与键盘；我们负责样式、语义补充、业务状态。
- 自研组件遵循 WAI-ARIA Authoring Practices：
  - Table：`role="table"` / 原生 table、`aria-sort`、caption、行选择标签。
  - DatePicker：grid 键盘导航、`aria-selected`、`aria-disabled`、月份切换 live region。
  - Form：label 关联、`aria-invalid`、`aria-describedby`、错误 `aria-live`。
  - Tabs：`aria-controls`、`aria-selected`、方向键。
- Focus：
  - 统一 `:focus-visible` ring token；
  - 不裸移除 outline；
  - Modal / Drawer 焦点陷阱与归还。
- 颜色：token 构建期校验对比度；不依赖颜色单独传达状态。
- 动效：`prefers-reduced-motion` 降级。
- 测试：
  - Playwright + axe 扫描每个 Demo 页面；
  - 键盘交互单测；
  - 发布前手工 NVDA / VoiceOver 抽查 P0 组件。

## 11. 测试架构

```text
单元/行为        Vitest + @solidjs/testing-library + jsdom + user-event
真实浏览器       Playwright：键盘、焦点、定位、虚拟滚动、axe
视觉回归         Playwright screenshot：MVP light/ltr/default；v1.0 dark/compact/RTL × 3 viewport
```

- **回归策略**：每个 bug 先加失败测试，再修复。

## 14. 性能与可靠性

- **Tree-shaking**：命名导出、`sideEffects` 仅 CSS、preserveModules、子路径导出。
- **按需 CSS**：全局或按组件；后续提供自动引入插件。
- **虚拟化**：Table / Tree / Select 大列表；固定行高优先。
- **避免重复渲染**：字段级/单元格级订阅；`For` 使用稳定 key；避免在渲染函数中创建大对象。
- **图标**：按图标引入，不整包导入。
- **运行时**：不引入大型工具库（lodash / moment / dayjs）；日期用 `@internationalized/date`，工具函数自研。
- **可靠性**：
  - 所有监听 / Observer 在 `onCleanup` 释放；
  - 弹层在路由切换 / 卸载时关闭；
  - 异步请求支持取消（Upload、Select 远程搜索）；
  - 错误边界由应用负责；组件不吞异常。

## 15. 架构决策摘要

| 决策 | 选择 | 影响 |
| --- | --- | --- |
| 包数量 | tokens / icons / core | 降低版本错配，兼顾复用 |
| CSS 引入 | 显式引入，JS 不 import CSS | 构建可预测；需文档强调 |
| 产物 | ESM + `dist/source` JSX 源码 + types + CSS；MVP 不做 CJS | 现代构建工具；老 Webpack 需评估 |
| SSR | MVP 主力 SPA/MPA 但 SSR 可用；`"solid"` 双构建为必备产物，M4 验渲染 / hydration；v1.0 全矩阵 | 避免 Phase 6 改 `exports` 结构造成 breaking |
| 包名 / 许可证 | 暂用 `@ui-design/*`；MIT（ADR-020） | scope 单点定义，改名不动组件 API |
| 响应式契约 | 值 / `Accessor<T>` + `resolveValue()`；Context 注入 getter | Form / Table 联动正确、API 一致 |
| 公共 API | 高层扁平 + 少量子组件 | 贴近 AntD 习惯，降低学习成本 |
| 底层原语 | Kobalte adapter 隔离 | 可替换，防类型泄漏 |
| 复杂组件 | Table / DatePicker / Form 自研渲染 | 控制体验与 API |
| 主题 | CSS 变量 + data 属性 | 无运行时、可微前端隔离 |
| 文档 | 自建 Vite + Solid | 同运行时，Demo 真实可交互 |
| Lint | oxlint（type-aware）+ Biome（Solid）+ Stylelint | 不依赖 ESLint/typescript-eslint，适配 TS 7 |
| 版本 | fixed + Changesets | 内部升级简单 |
